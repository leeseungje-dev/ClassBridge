# ClassBridge 기획 및 개발 계획

개인 어학 강사가 학생 정보, 수업 일정, 출결, 수업일보를 관리하고
누적된 학습 관찰 기록을 다음 수업 준비에 활용하는 웹 서비스입니다.

계획 갱신일: 2026-10-29
면접 예정일: 2026-11-12

## 1. 사용자와 핵심 흐름

### 사용자

- 개인 또는 소규모 어학 강사
- 학생은 로그인 계정을 만들지 않습니다.
- 로그인한 강사가 자신의 학생과 관련 기록을 관리합니다.

### 핵심 흐름

```text
회원가입·로그인
→ 학생 등록
→ 학생별 수업 등록
→ 출결 처리
→ 출석 수업의 일보와 관찰 항목을 한 화면에서 작성
→ 한 번의 저장으로 함께 보관
→ 학생 상세에서 다음 수업과 누적 관찰 기록 확인
```

### 설계 방향

- 같은 관찰 내용을 두 번 입력하지 않습니다.
- 수업일보 화면은 해당 수업의 전체 기록을 보여줍니다.
- 학생 상세 화면은 여러 수업의 관찰 기록을 모아 보여줍니다.
- 두 화면은 같은 DB 데이터를 조회하며 별도로 복사 저장하지 않습니다.
- 학생의 능력이나 습관을 자동으로 평가하지 않습니다.

- 학생 입력값 검사와 강사별 접근 제한
- 학생별 수업 등록·목록 조회
- 수업 일시순 정렬과 일시 변경
- 예정·출석·결석·취소 상태 변경

## 3. 기술과 실행 환경

| 구분 | 사용 기술 |
|---|---|
| 언어 | Java 21, HTML |
| 웹 처리 | Spring Boot, Spring MVC |
| 화면 표시 | Thymeleaf |
| 인증·인가 | Spring Security, 세션 |
| DB 접근 | MyBatis, Oracle JDBC |
| DB | Oracle Database |
| 코드 생성 보조 | Lombok |
| 빌드 | Maven |
| 테스트 | JUnit, Spring Boot Test |
| 개발 도구 | Spring Tools/Eclipse, VS Code, SQL Developer |
| 배포 | Docker, Render |
| 공개 환경 DB | Oracle Autonomous AI Database |
| 버전 관리 | Git, GitHub |

- Controller가 요청을 받고 Service를 호출합니다.
- Service가 입력값과 업무 규칙을 검사합니다.
- Mapper와 XML SQL이 DB 조회·저장·수정을 담당합니다.
- Controller는 Model에 데이터를 담고 Thymeleaf 화면을 반환합니다.
- 로컬 개발 DB와 공개 환경 DB는 분리합니다.
- 비밀번호와 Oracle Wallet은 Git에 포함하지 않습니다.

## 4. 데이터 구조

```text
APP_USERS
└── STUDENTS
    └── LESSONS
        └── LESSON_REPORTS
            └── LEARNING_OBSERVATIONS
```

| 관계 | 규칙 |
|---|---|
| 강사 → 학생 | 강사 한 명에게 학생 0명 이상 |
| 학생 → 수업 | 학생 한 명에게 수업 0건 이상 |
| 수업 → 수업일보 | 수업 한 건에 일보 0건 또는 1건 |
| 수업일보 → 관찰 기록 | 일보 한 건에 관찰 기록 0건 이상 |

자식 데이터는 각각 부모 데이터 한 건에 속합니다.
모든 관계는 자식이 별도의 ID를 기본 키로 사용하는 비식별 관계입니다.

자료형·길이·제약조건은 docs/docs-data-design.md에서 관리합니다.

### User — 구현 완료

- id
- email
- password
- role
- createdAt

### Student — 구현 완료

- id
- instructorId
- name
- learningStartDate
- currentLevel
- instructorMemo
- createdAt

### Lesson — 구현 완료

- id
- studentId
- lessonAt
- status
- statusMemo
- createdAt

상태값:
- SCHEDULED: 예정
- ATTENDED: 출석
- CANCELLED: 취소
- ABSENT: 결석

### LessonReport — 구현 예정

- id
- lessonId: 연결된 수업, 중복 불가
- content: 수업에서 다룬 내용, 필수
- nextCheck: 다음 수업에서 확인할 내용, 선택
- createdAt
- updatedAt

학생 반응을 적는 별도 필드는 두지 않습니다.
학생 반응과 수행 내용은 관찰 항목에 기록합니다.

### LearningObservation — 구현 예정

- id
- lessonReportId: 연결된 수업일보
- category: 관찰 분류, 필수
- item: 관찰 항목, 필수
- memo: 구체적인 관찰 내용, 필수
- createdAt
- updatedAt

관찰 분류:
- GRAMMAR: 문법
- EXPRESSION: 표현
- PRONUNCIATION: 발음
- SPEAKING: 회화
- LISTENING: 듣기
- OTHER: 기타

분류는 정해진 값 중 선택합니다.
관찰 항목과 구체적인 내용은 강사가 직접 입력합니다.

## 5. 수업일보 작성·수정 규칙

아래 규칙은 앞으로 구현할 기능의 기준입니다.

1. 로그인한 강사는 자신의 학생에게 속한 일보만 조회·작성·수정합니다.
2. ATTENDED 상태의 수업에만 일보를 작성·수정합니다.
3. 수업당 일보는 최대 한 건이며 DB의 UNIQUE 제약조건으로도 보장합니다.
4. 일보가 있으면 수업 상태를 ATTENDED 이외의 값으로 변경하지 못하게 합니다.
5. 수업 내용은 필수이고 다음 확인 사항은 선택 입력입니다.
6. 관찰 기록은 없어도 일보를 저장할 수 있습니다.
7. 관찰 항목을 추가했다면 분류·항목·내용은 모두 입력해야 합니다.
8. 일보와 관찰 항목을 하나의 트랜잭션으로 저장합니다.
9. 일부 항목에서 실패하면 전체 저장을 취소합니다.
10. 일보 수정 화면에서 관찰 항목의 추가·변경·삭제를 지원합니다.
11. 최초 작성 시각은 유지하고 수정 시각은 UPDATE SQL에서 갱신합니다.

### 메모의 역할 구분

| 위치 | 기록 내용 |
|---|---|
| 학생의 강사 메모 | 학습 목표, 수업 선호 등 전반적인 참고사항 |
| 수업의 상태 메모 | 취소·결석 등 출결 관련 사유 |
| 일보의 수업 내용 | 해당 수업에서 가르치고 연습한 내용 |
| 관찰 기록 | 학생의 반응, 어려움, 성취 등 구체적인 내용 |
| 일보의 다음 확인 사항 | 다음 수업에서 다시 확인할 내용 |

### 학생 삭제 정책

현재 외래 키에는 하위 기록 자동 삭제를 설정하지 않았습니다.
연결된 수업이 있는 학생의 삭제 처리와 안내는 보완이 필요합니다.

기록 보존과 삭제 범위를 정한 뒤 구현하며,
그전까지 하위 데이터가 자동으로 삭제된다고 안내하지 않습니다.

## 6. 화면 구성

### 현재 화면

- 홈
- 회원가입
- 로그인
- 학생 목록·등록·상세·수정
- 학생 없음 안내
- 학생별 수업 목록·등록
- 수업 일시 수정
- 수업 상태 및 상태 메모 변경
- 수업 없음 안내

### 추가할 수업일보 화면

- 작성: 수업 내용, 관찰 항목 여러 개, 다음 확인 사항
- 상세: 해당 수업의 일보와 관찰 항목 표시
- 수정: 일보 내용 수정과 관찰 항목 추가·변경·삭제

저장 버튼 한 번으로 일보와 관찰 항목을 함께 저장합니다.
관찰 기록을 별도로 다시 작성하는 화면은 만들지 않습니다.

### 확장할 학생 상세 화면

- 학생 기본 정보와 강사 메모
- 다음 예정 수업
- 가장 최근 수업일보의 다음 확인 사항
- 누적 학습 관찰 이력
- 분류별 관찰 기록 조회
- 해당 수업일보로 이동하는 링크
- 학생 수정·삭제와 수업 목록 이동

다음 수업은 현재 이후의 SCHEDULED 수업 중 가장 가까운 수업입니다.

최근 일보는 작성 시각이 아닌 연결된 수업 일시를 기준으로 찾습니다.
최근 일보에 다음 확인 사항이 없으면 없다고 표시합니다.

관찰 이력은 수업 일시의 최신순으로 보여줍니다.
기록이 없으면 안내 문구를 표시합니다.

## 7. 요청 처리 방식

- 현재는 Thymeleaf 화면을 반환하는 Spring MVC 방식입니다.
- GET은 화면 표시·조회에 사용합니다.
- POST는 등록·수정·삭제 요청에 사용합니다.
- 상태 변경과 상태 메모는 같은 폼에서 함께 저장합니다.
- 별도의 /api 경로나 REST API 전환은 이번 작업 범위가 아닙니다.
- 신규 일보 경로는 Controller를 작성할 때 확정합니다.
- Spring Security의 CSRF 보호를 유지합니다.
